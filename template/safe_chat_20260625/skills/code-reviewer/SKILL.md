# Code Reviewer Skill

代码审查是保证代码质量的重要环节，遵循以下标准和流程。

## 审查维度

### 1. 逻辑正确性
- 功能是否实现了需求
- 边界条件是否处理
- 错误处理是否完善

### 2. 代码可读性
- 命名是否清晰有意义
- 函数是否单一职责
- 注释是否准确必要

### 3. 性能考量
- 是否有不必要的循环/重复计算
- 数据库查询是否优化
- 是否有内存泄漏风险

### 4. 安全审计
- 输入是否验证
- SQL/命令注入风险
- 敏感信息是否泄露
- 权限控制是否正确

### 5. 测试覆盖
- 核心逻辑是否有测试
- 边界条件是否覆盖
- 异常场景是否测试

## 审查流程建议

1. **静态分析**：快速扫描代码结构，了解整体架构
2. **逻辑审查**：逐函数检查业务逻辑正确性
3. **安全审查**：重点检查输入验证、权限控制、敏感数据处理
4. **性能审查**：分析算法复杂度、数据库访问模式
5. **输出报告**：整理问题列表，给出修复建议

## 审查报告格式

建议按以下格式输出审查结果：

```markdown
# 代码审查报告

## 文件信息
- 文件路径: xxx
- 审查时间: xxx

## 问题列表

### 🔴 严重问题
| 位置 | 问题 | 建议 |
|------|------|------|

### 🟡 中等问题
| 位置 | 问题 | 建议 |
|------|------|------|

### 🟢 优化建议
| 位置 | 问题 | 建议 |
|------|------|------|

## 总结
- 严重: N
- 中等: N
- 优化: N
```

## 常用审查命令参考

```bash
# Python 语法检查
python3 -m py_compile file.py

# Git 历史查看
git log --oneline -10
git diff HEAD~1
```

| 评级 | 说明 |
|------|------|

| B | 良好，有少量优化建议 |
| C | 需要修改，有中等问题 |
| D | 严重问题，需要大改 |
